# 我在 Mac 上用 Claude Code 踩过的坑

我平时拿 Claude Code 写中文脚本、剪视频，也直接在项目里改代码。用下来最耽误事的两个坑：一个是手机扣了钱，打开 Claude 还是免费版；另一个是代码改到一半额度见底，换个号重开窗口，前面聊的全白费。

下面是我自己实测跑通的一套做法，踩过的坑和没法证实的猜测都分开写，图个实在。

## 1. 套餐怎么选：为什么用多个 Pro 轮换

我现在是 **3 个 Pro 账号** 换着用。

说白了，想让一个号永远不出事几乎不可能。我见过稳了好几个月的 Pro，刚升 Max 就被限制了。具体平台怎么判的外面没人知道，但 100 刀、200 刀的号真出事太肉疼，不如开几个 Pro 轮着用，丢一个补一个不心疼，手里随时有替补。

如果一个 Pro 已经够你用，这仓库默认单账号就能跑，不用上来就折腾多号。

## 2. 账号、订阅方式和身份验证（KYC）

### 别再用 Apple 礼品卡新订阅

我用 Apple 礼品卡余额新订 Pro 时，遇到过**钱扣了、账号还是免费版**的情况，而且现在新订阅碰上炸单的概率非常高。老号续费目前大多还行，但千万别取消重订。

万一已经扣款没到账，先别急着再付一遍，按顺序对三件事：

1. 打开 Apple 收据，看清楚是**哪个 Apple 账户**付的钱（iCloud 和 App Store 登了不同账号的话，很容易找错地方）。
2. 打开 Claude，核对当前登的**邮箱**和**套餐状态**。
3. 确认没登错，就用买单那个商店账号点一下「恢复购买」；还是不行，直接拿订单号找客服或申请退款。苹果退款不是每次都给退，别赌第二次。[Apple 恢复购买](https://support.apple.com/zh-cn/108096) · [Apple 退款说明](https://support.apple.com/zh-cn/118223) · [Claude 账单说明](https://support.claude.com/en/articles/8325618-paid-plan-billing-faqs)

后来我改在 Android 端走 **Google Play** 订阅，Pro 直接就到账了。不管用哪种渠道，付完款把商店账号、Claude 邮箱和开通状态对一遍最稳。[Claude Android 订阅说明](https://support.claude.com/en/articles/9612892-how-do-i-sign-up-for-claude-pro-on-claude-for-android)

### 邮箱验证和 KYC 别搞混

建号和升级的时候，容易把两家平台的弹窗混在一起：

- 新邮箱刚登上去没多久，又被要求发短信验证——这是邮箱那边的风控，去邮箱侧解决。
- 刚升 Pro 弹出身份验证（KYC）——这是 Claude 这边的正常认证，我直接拿护照按官方页面提交，秒过。[Claude 身份验证说明](https://support.claude.com/en/articles/14328960-identity-verification-on-claude)

如果是用了一阵子突然弹 KYC，按经验来看这个号大概率是被盯上了，就算过了也建议当备用，别把主力活全压在上面。

## 3. 多个账号怎么切：从双开到 cmux 5% 自动接力

只有两个号的时候，我是一个登桌面端、一个登 CLI，官方原生支持，省心。唯一的坑是，终端底栏有时候会显示成桌面端那个号的额度，光看百分比根本分不清是谁的。现在我都先跑一遍 `claude auth status` 看邮箱，再进会话用 `/usage` 看实际剩余。

加到三个号以后，我看过 CC Switch 和 Magpie，但我的项目都在 **cmux** 里跑，不想切来切去把当前窗格的上下文弄丢，就自己写了个本地接力脚本：

1. **登录全走官方流程**：每个号配一个独立的 `CLAUDE_CONFIG_DIR`，不经过任何第三方切号服务。第一次登录由官方 Claude Code 拉起浏览器授权，登完一定用 `auth status` 核对邮箱——我就踩过目录写的是 C，浏览器里顺手点成了 B 的坑。[官方多账号登录说明](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)
2. **为什么留 5% 就切**：网上有人说别把额度蹬满，不然容易封，我自己倒没碰见。留这 **5%** 单纯是不想让手头的活被硬打断。脚本等这一轮彻底空闲、没有后台任务和未发送草稿时，再去读 `/usage`，五小时或周额度任一项 `<= 5%` 就换下一个有余量的号。遇到登录失效、账号受限或读不出额度，直接停住不瞎切。
3. **在原窗格接着聊**：换号时在同一个 cmux 窗格、同一个目录里用新号拉起官方 Claude Code，通过 `--resume` 接上刚存好的聊天记录，再加 `--fork-session` 开个新分支。项目文件都在原地，下一句直接接着问（正在跑的外部命令没法靠聊天记录续上，但对话内容都在）。[Claude Code 续聊参数](https://code.claude.com/docs/en/cli-reference)

这个脚本已经放进仓库里了，可以先拿两三个号在单个窗格试跑，顺手了再绑到 cmux 快捷键。多说一句，官方只写了独立登录和续聊参数，对按额度轮换没有任何承诺，按自己需要决定用不用。[多账号与接力用法](accounts.md)

## 4. 网络、设备和日常用法：少折腾，减少对抗

### 网络：核心是稳，别迷信所谓“家宽”

我用的就是机房线路，没必要花冤枉钱折腾来路不明的所谓“家宽”，别用万人共享的就行。关键就两点：**电脑和手机固定走同一套稳定出口**，以及**搞清楚请求到底有没有走对地方**。

我自己排查固定查三样：

1. **查终端真实出口**：在 cmux 里随便发一句话，去代理的连接记录里按时间找对应域名，看命中的是不是自己配的分流规则、走的是不是目标节点。光在浏览器开个查 IP 网页，只能看浏览器，代表不了终端。
2. **查 DNS**：开了 fake-ip 之后，Mac 系统里看到的只是本地映射地址，要对照代理配置和查询记录确认上游 DNS 没有乱跑。
3. **查浏览器 WebRTC**：在平时用来登录的浏览器里单独测一下 WebRTC，看有没有漏出别的公网地址。[网络检查与分流示例](network.md)

### 设备：干净就行

我之前在 Windows 上乱折腾过几次，后来好几个号露头就秒，怀疑是设备被标了。换到一台干净的 Mac，重新理好分流和 DNS 保护之后，一直稳到现在。

### 日常使用：大大方方干活

我平时就是纯中文对话，让它写自媒体稿子、改代码，从来没改过系统时区，也没装老外昼伏夜出。对抗越多、装得越刻意，反而越容易出事。

真正别碰的是高强度高并发刷量（像蒸馏一样）、逆向或者其他违规操作。正常干活，心态放平——再稳的方案也不敢打包票永远不封，多个 Pro 备着，不耽误干活才是最实在的。
